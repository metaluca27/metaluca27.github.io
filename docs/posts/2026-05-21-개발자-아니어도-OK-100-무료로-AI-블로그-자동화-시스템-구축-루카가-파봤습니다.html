개발자 아니어도 OK! 100% 무료로 AI 블로그 자동화 시스템 구축, 루카가 파봤습니다!

2026-05-21 테크 Luka

안녕하세요, 코딩은 못 하지만 IT가 너무 궁금한 비개발자 루카(Luka)입니다.

늘 블로그에 글을 쓰고 싶다는 마음은 굴뚝같았는데, 콘텐츠 기획하고, 글 쓰고, 이미지 찾고, 발행 버튼 누르는 모든 과정이 생각보다 시간과 에너지를 많이 잡아먹더라고요. 그러다 문득 "AI가 글도 써준다는데, 이걸 블로그에 자동으로 발행까지 할 수는 없을까?" 하는 호기심이 발동했습니다. 심지어 "100% 무료"로 가능하다고? 에이, 설마. 제가 직접 알아보고 부딪혀 봤습니다. 오늘은 저처럼 개발 지식은 없지만, AI 시대에 블로그 자동화라는 꿈을 꾸는 분들을 위해 제가 파고들어 구축한 100% 무료 AI 블로그 자동화 시스템 구축 방법을 공유해볼까 합니다.

AI 시대, 블로그 자동화가 왜 궁금했을까요? (루카의 솔직한 고백)

사실 처음에는 "자동화"라는 말에 살짝 거부감이 있었어요. '블로그는 결국 사람의 진솔한 이야기를 담는 곳인데, 그걸 기계가 자동으로 해버리면 무슨 의미가 있지?' 하고요. 그런데 며칠 밤낮으로 검색하고 자료를 찾아보니, 제가 생각했던 것과는 좀 다르더군요. 여기서 말하는 "자동화"는 블로그의 영혼까지 AI에게 맡기는 게 아니라, 반복적이고 귀찮은 작업을 줄여서 제가 오롯이 아이디어 구상과 글의 질을 높이는 데 집중할 수 있도록 돕는 시스템에 가까웠습니다.

특히, "무료"라는 단어가 제 비개발자 레이더를 강하게 자극했습니다. 개발 지식도 없는데 돈까지 내면서 무언가를 시도하기는 부담스러웠거든요. 하지만 찾아보니, 정말로 단 한 푼도 들이지 않고 블로그 콘텐츠 생성부터 발행까지 자동화할 수 있는 방법들이 있었습니다. 여기서 '가능하겠는데?' 하는 확신이 들었죠.

'거저'로 시스템 구축하기 위한 핵심 도구들 (제가 파헤쳐 본 것들)

100% 무료 자동화 시스템을 구축하려면 세 가지 핵심 도구가 필요하다는 걸 알아냈습니다. 1. 정적 사이트 생성기 (Static Site Generator, SSG): 글을 예쁜 웹페이지로 만들어주는 도구 2. AI 콘텐츠 생성 도구: 글의 아이디어를 내고 초안을 써주는 도우미 3. 무료 호스팅 + 자동 배포 시스템: 만들어진 웹페이지를 인터넷에 올리고, 제가 글만 추가하면 자동으로 반영해주는 똑똑한 서버

1. 정적 사이트 생성기 (Static Site Generator, SSG): 빠르고, 가볍고, 무료!

저는 처음에 "블로그는 워드프레스!"라고만 생각했어요. 그런데 워드프레스는 서버도 필요하고 데이터베이스도 필요해서 유지 비용이 든다는 걸 알게 됐죠. 반면 정적 사이트 생성기(SSG)는 글을 미리 HTML 파일로 만들어두는 방식이라, 서버에서 그때그때 페이지를 만들 필요가 없어 훨씬 빠르고 보안에도 강하며, 무엇보다 거의 모든 기능을 무료로 사용할 수 있습니다.

대표적인 SSG로는 Jekyll, Hugo, Eleventy 등이 있었습니다. 제가 찾아본 특징을 표로 정리해봤어요.

특징 Jekyll Hugo Eleventy
개발 언어 Ruby Go JavaScript (Node.js)
빌드 속도 느림 (100개 포스트 기준 30초~1분 이상) 매우 빠름 (수백 개 포스트 1~5초 이내) 빠름 (100개 포스트 기준 5~15초)
초기 학습 곡선 중간 (GitHub Pages와 궁합 좋음) 중간 (템플릿 엔진이 다소 독특) 낮음 (JavaScript 익숙하다면 쉬움)
테마/플러그인 매우 풍부 풍부 계속 성장 중
커뮤니티 매우 활발 (오래됨) 활발 활발 (최신 트렌드 반영)
비고 GitHub Pages 공식 지원 Go 언어 덕분에 압도적인 속도 설정이 자유롭고 가벼움

저는 GitHub Pages와의 완벽한 궁합과 풍부한 테마 덕분에 Jekyll을 선택했습니다. 빌드 속도가 느리다는 단점이 있지만, 개인 블로그에서는 크게 체감되지 않을 것이라고 판단했어요. (사실 GitHub Actions가 알아서 해줄 거니까요!)

2. AI 콘텐츠 생성 도구: 든든한 글쓰기 파트너

블로그 자동화의 핵심, 바로 AI가 글을 쓰는 부분입니다. 저는 ChatGPT (GPT-3.5 무료 버전)와 Gemini (무료 버전)를 주로 사용했습니다. 이 친구들은 100% 무료이면서도 제가 상상했던 것보다 훨씬 똑똑하더군요.

  • 아이디어 구상: "AI 시대에 100% 무료 블로그 자동화 시스템 구축 방법이라는 주제로 블로그 포스팅 아이디어 5가지와 각 소제목을 제안해 줘."
  • 초안 작성: "위 아이디어 중 '무료 호스팅과 자동 배포' 부분에 대해 비개발자도 이해하기 쉽게 설명하는 글을 800자 이내로 작성해 줘."
  • SEO 키워드 제안: "작성된 글에 대한 SEO 키워드 5가지와 메타 디스크립션 문구를 추천해 줘."

이런 식으로 프롬프트를 던지면 놀랍도록 상세한 답변을 내어줍니다. 물론 AI가 쓴 글을 그대로 발행하는 건 피했습니다. 여전히 사람의 손길이 닿아야 자연스럽고, 저만의 개성을 담을 수 있기 때문이죠. 저는 AI가 준 초안을 바탕으로 제가 직접 알아본 내용, 루카의 경험, 그리고 제 생각을 덧붙여 글을 완성하는 방식으로 활용했습니다. 이렇게 하니 글 쓰는 시간이 30% 이상 단축되는 느낌을 받았습니다.

3. 무료 호스팅 + 자동 배포 시스템: 내가 코드를 몰라도 알아서 척척!

이제 AI가 써준 글을 SSG로 예쁘게 만들었으니, 이 파일을 인터넷에 올려야겠죠? 여기에 제가 찾은 100% 무료 호스팅이자 자동 배포의 핵심은 바로 GitHub Pages와 GitHub Actions의 조합입니다.

  • GitHub Pages: 이건 GitHub에서 제공하는 무료 웹 호스팅 서비스입니다. 제 블로그 파일을 GitHub 리포지토리에 올려두면, GitHub가 자동으로 웹사이트로 만들어줍니다. 매우 편리하고, 무료이며, 안정적입니다.
  • GitHub Actions: 이게 바로 "자동화의 뇌"입니다. GitHub Actions는 제가 GitHub 리포지토리에 새로운 글을 올리거나 수정한 내용을 푸시할 때마다, 미리 정해둔 일련의 작업(SSG로 블로그 빌드 -> GitHub Pages로 배포)을 자동으로 실행해줍니다. 저는 그저 글을 작성해서 GitHub에 올리기만 하면, 나머지는 이 친구가 알아서 처리해주는 거죠! GitHub Actions는 무료 계정 기준 월 2,000분(Linux 기준)의 무료 사용 시간을 제공하는데, 일반적인 블로그 배포는 한 번에 1분도 채 걸리지 않으니 사실상 무제한에 가깝습니다.

비개발자 루카의 100% 무료 블로그 자동화 시스템 구축 과정 (Step-by-step)

자, 이제 제가 직접 블로그 자동화 시스템을 어떻게 만들었는지 단계별로 보여드릴게요. 저는 Jekyll을 기준으로 설명하겠습니다.

1. GitHub 리포지토리 생성 및 Jekyll 초기 설정

가장 먼저 GitHub에 리포지토리를 만들고, Jekyll 블로그의 기본 구조를 가져와야 합니다. 저는 이미 만들어진 Jekyll 테마를 복제하는 방법을 사용했습니다.

# 1. GitHub에 새로운 리포지토리 생성 (예: my-ai-blog)
#    - 'Public'으로 설정해야 GitHub Pages 무료 호스팅이 가능합니다.
#    - 'Add a README file'은 선택 사항입니다.

# 2. 로컬 컴퓨터에 GitHub 리포지토리 복제 (터미널/명령 프롬프트에서)
git clone https://github.com/your-github-username/my-ai-blog.git
cd my-ai-blog

# 3. Jekyll 기본 테마를 복제하고 기존 내용 삭제
#    (이 방법은 기존 리포지토리 내용을 덮어씁니다. 주의!)
git clone https://github.com/jekyll/jekyll-starter-theme tmp_jekyll_theme
mv tmp_jekyll_theme/* .
mv tmp_jekyll_theme/.git* .
rm -rf tmp_jekyll_theme

# 4. _config.yml 파일 설정 (핵심!)
#    - 'my-ai-blog/_config.yml' 파일을 텍스트 편집기로 열고 아래 내용을 수정/추가하세요.
#    - 'baseurl'은 GitHub Pages 프로젝트 이름(리포지토리 이름과 동일)을 넣어야 합니다.
#    - 'url'은 사용자 GitHub Pages URL (예: https://your-github-username.github.io)
#    - 'theme'은 사용 중인 테마 이름 (예: minima 또는 jekyll-theme-cayman)
#    - 'remote_theme: jekyll/minima' 와 같이 설정할 수도 있습니다.

# 5. 변경사항을 GitHub 리포지토리에 푸시
git add .
git commit -m "Initial Jekyll setup for AI blog automation"
git push -u origin main

이렇게 하면 GitHub 리포지토리에 Jekyll 블로그의 기본 파일들이 올라갑니다. _config.yml 설정은 특히 중요하니 꼼꼼히 확인해주세요! 특히 baseurl은 https://your-github-username.github.io/your-repository-name 형태가 되도록 리포지토리 이름과 일치시켜야 합니다.

2. AI로 콘텐츠 생성 및 Markdown 파일로 추가

이제 글을 작성할 차례입니다. 앞서 말했듯이 ChatGPT나 Gemini를 활용하여 초안을 만들고, 제 생각을 덧붙여 글을 완성합니다.

작성한 글은 _posts 폴더 안에 Markdown 형식으로 저장해야 합니다. 파일명은 YYYY-MM-DD-제목.md 형식이어야 합니다.

예시: _posts/2024-07-20-ai-blog-automation-guide.md

categories: [테크, AI, 블로그]
tags: [AI블로그, 블로그자동화, 무료블로그, 비개발자, GitHubPages]
---

안녕하세요, 코딩은 못 하지만 IT가 너무 궁금한 비개발자 루카(Luka)입니다.

(여기에 AI가 생성한 글과 루카가 수정한 본문 내용이 들어갑니다.)

중요한 점: Markdown 파일 상단에 ---로 감싸진 부분을 프론트 매터(Front Matter)라고 합니다. 여기에 글의 제목, 날짜, 카테고리, 태그 등을 지정해주면 Jekyll이 이를 기반으로 자동으로 예쁜 블로그 포스팅 페이지를 만들어줍니다.

3. GitHub Actions로 자동 배포 설정하기 (자동화의 핵심!)

이제 가장 중요한 자동화 부분입니다. 제가 _posts 폴더에 새 글을 추가하고 GitHub에 푸시(push)하면, GitHub Actions가 자동으로 블로그를 빌드하고 GitHub Pages로 배포하도록 설정할 겁니다.

  1. 리포지토리 내 .github/workflows 폴더 생성: 이 폴더 안에 deploy.yml (파일명은 자유)이라는 파일을 만들 겁니다.
    • my-ai-blog/.github/workflows/deploy.yml
  2. deploy.yml 파일 내용 작성: 아래 코드를 그대로 복사해서 붙여넣으세요. (혹은 Jekyll 버전이나 GitHub Actions 버전에 따라 조금 수정될 수 있습니다.)
name: Deploy Jekyll to GitHub Pages

on:
  push:
    branches:
      - main # 'main' 브랜치에 푸시될 때마다 워크플로우 실행
      # 만약 기본 브랜치 이름이 'master'라면 'master'로 변경하세요.

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest # 최신 Ubuntu 환경에서 실행

    steps:
      - name: Checkout repository # GitHub 리포지토리 코드 가져오기
        uses: actions/checkout@v4

      - name: Set up Ruby # Jekyll이 필요한 Ruby 환경 설정
        uses: ruby/setup-ruby@v1
        with:
          ruby-version: '3.x' # 최신 Ruby 3.x 버전 사용
          bundler-cache: true # Gem 캐싱으로 빌드 속도 향상

      - name: Install Jekyll dependencies # Jekyll 필요한 라이브러리 설치
        run: bundle install

      - name: Build Jekyll site # Jekyll 블로그 빌드
        run: bundle exec jekyll build --config _config.yml # _config.yml 파일로 사이트 빌드

      - name: Deploy to GitHub Pages # 빌드된 사이트를 GitHub Pages로 배포
        uses: peaceiris/actions-gh-pages@v3
        if: github.ref == 'refs/heads/main' # main 브랜치에서만 배포
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }} # GitHub 토큰 (자동 생성됨)
          publish_dir: ./_site # 빌드된 결과물 폴더 (Jekyll은 보통 _site 폴더에 저장)
          # cname: blog.yourdomain.com # (선택 사항) 사용자 정의 도메인 설정 시 주석 해제 후 본인 도메인 입력

이 파일을 저장하고 GitHub 리포지토리에 푸시하면 (새로운 글을 푸시하듯이 git add ., git commit -m "Add GitHub Actions workflow", git push 명령어 사용), GitHub Actions가 자동으로 실행됩니다.

실행 과정은 GitHub 리포지토리의 Actions 탭에서 확인할 수 있습니다. 초록색 체크 표시가 뜨면 성공적으로 배포된 것이고, 잠시 후 GitHub Pages URL에서 변경된 블로그를 확인할 수 있을 거예요!

비개발자가 헷갈리기 쉬운 부분 (루카의 삽질 기록)

저처럼 코딩을 모르는 비개발자가 이 과정을 따라 하면서 가장 많이 헤맸던 부분들을 정리해봤습니다.

1. _config.yml 파일 설정 (특히 baseurl!)

  • 문제: _config.yml 파일의 baseurl 설정을 잘못해서 블로그가 제대로 보이지 않거나 CSS/이미지가 깨지는 경우가 많았습니다. 특히 GitHub Pages는 https://your-username.github.io/your-repository-name 형태로 URL이 만들어지는데, baseurl을 /your-repository-name으로 설정하지 않으면 이미지가 로드되지 않거나 링크가 제대로 작동하지 않습니다.
  • 해결: 리포지토리 이름을 baseurl: /your-repository-name으로 정확히 입력해야 합니다. 만약 your-username.github.io처럼 사용자 페이지 형태로 블로그를 만든다면 baseurl:을 비워두거나 baseurl: ""로 설정해야 합니다. 공식 Jekyll GitHub Pages 가이드를 여러 번 읽어보며 정확한 값을 확인했습니다.

2. GitHub Actions YAML 파일 문법 (띄어쓰기, 들여쓰기!)

  • 문제: YAML 파일은 띄어쓰기와 들여쓰기가 정말 중요합니다. 한 칸만 틀려도 "Error: YAMLSyntaxError" 같은 에러를 뿜어내며 워크플로우가 실패합니다. 저는 스페이스바 대신 탭(Tab) 키를 썼다가 한참 헤매기도 했고, 줄 맞춤이 어긋나서 여러 번 재시도했습니다.
  • 해결: YAML 파일을 편집할 때는 텍스트 에디터의 자동 들여쓰기 기능을 활용하고, 반드시 스페이스바 2칸 또는 4칸으로만 들여쓰기를 통일해서 사용하세요. GitHub 웹 에디터에서 직접 수정하면 기본적인 문법 검사를 해주기 때문에 에러를 줄일 수 있습니다. 또한, GitHub Actions 공식 문서에 예시가 많으니 참고하면 좋습니다.

3. GitHub Pages Custom Domain 설정 (DNS 레코드!)

  • 문제: your-username.github.io 대신 blog.mydomain.com처럼 제 도메인을 연결하고 싶을 때, CNAME 레코드와 A 레코드 설정이 너무 헷갈렸습니다. "CNAME? A 레코드? 이게 뭔데?" 싶었죠.
  • 해결: 간단히 말해, 서브 도메인(예: blog.mydomain.com)을 연결할 때는 CNAME 레코드를, 최상위 도메인(예: mydomain.com)을 연결할 때는 A 레코드를 사용하면 됩니다.
    • CNAME 설정: 도메인 구매 사이트(카페24, 가비아 등)에서 DNS 설정으로 들어가 Type: CNAME, Name: blog (서브도메인 이름), Value: your-username.github.io 로 설정하면 됩니다.
    • A 레코드 설정: Type: A, Name: @ (최상위 도메인), Value: 185.199.108.153 (GitHub Pages IP 주소, 여러 개 있을 수 있음)로 설정합니다. GitHub Pages 공식 IP 주소는 여러 개가 있으니 GitHub 공식 문서에서 최신 정보를 확인하는 것이 좋습니다.
    • 설정 후에는 CNAME이라는 파일에 연결할 도메인 이름을 한 줄로 입력하여 블로그 리포지토리의 최상단에 푸시해야 합니다. (예: blog.yourdomain.com)
